## Визначення варіанта

Варіант визначається остачею від ділення номера залікової книжки студента на 3\. За відсутності залікової книжки використовувати порядковий номер студента у списку групи.

*`V = N mod 3`*,

Де	*`V`* — номер варіанту завдання  
	*`N`* — номер залікової книжки студента

    N = 5
    V = 5 mod 3
    V = 2

### Варіант V=2: Система управління замовленнями

#### Ієрархія даних 

Ієрархію даних реалізувати за допомогою sealed interface та record. Усі інтерфейси та записи (records), які описують ієрархію даних мають бути публічними та знаходитися в пакеті `package ua.kpi.comsys.dop;`

`+ Notification`  
`|--- TextMsg(String sender, String text)`  
`|--- ImageMsg(String sender, String url, int sizeKb)`  
`|--- AudioMsg(String sender, int durationSeconds)`

Валідація в конструкторах record:

- `sender`, `text`, `url` не можуть бути `null` або порожніми/пробільними (`IllegalArgumentException`).  
- `sizeKb` та `durationSeconds` мають бути обов'язково `> 0` (`IllegalArgumentException`).

#### Клас-обробник та детальна логіка трансформації

Сигнатура:

`package ua.kpi.comsys.dop;`  
`public class NotificationProcessor {`  
    `public String process(Notification notification) { ... }`  
`}`

Поведінка та логіка обробника:

- Якщо notification \== null, кидати IllegalArgumentException("Notification cannot be null").  
- Використовує switch expression з pattern matching та повертає Text Block:    
  - Для TextMsg:

    `Notification: TEXT`

    `From: _`

    `Message:` 

- Для ImageMsg:

  `Notification: IMAGE`

  `From: _`

  `URL: _ (_ KB)`

- Для AudioMsg:

  `Notification: AUDIO`

  `From: _`

  `Duration: _ seconds`
